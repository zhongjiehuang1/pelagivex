# PelagiVex 的下一步：把本机速度变成可验证的视觉能力

研究记录更新于 2026-11-07。内容包括已完成的本机精度与硬件实验、两段真实标注视频的传播诊断，以及待检验的论文假设。

## 1. 当前证据与“极致”的具体含义

目前可靠的工程起点是：YOLOE 自动识别保持新帧更新，SAM 在后台补充细轮廓，过期或关联不可靠时退回当前原生分割。[v0.7 实现、原始结果与复跑方法](REALTIME_CONTOURS.md)保留了以下不同层次的证据：

- 人工设定 30 Hz 输入的离线调度实验，异步检测约 26.4–27.2 FPS；渲染、深度和轮廓真值未纳入。
- Camo 的短时界面观察约 19–23 FPS 显示，也出现共享资源竞争下更低的读数；它不是固定时长的性能保证。
- 59 项 Swift 检查和已有 Python 检查覆盖实现约束；像素一致性探针比较的是两种实现，不是人工真值。
- 当前应用管线还没有在逐帧独立边界真值上评价，因而无法声称 SAM 细化或框传播提升了真实边界精度；新完成的两段 DAVIS 诊断只隔离了理想框传播的能力边界。

下一步应最大化的是**单位本机计算预算下，在用户实际看到的时刻仍然正确的识别、身份和边界**。显示频率、检测频率、SAM 更新频率、结果年龄及边界质量必须分别记录。不能用重复显示同一帧或保留稳定但错误的轮廓来提高指标。

### 1.1 选择性混合精度加快检测，但改变部分分数与掩膜

YOLOE 的混合精度实验保留类别索引及相关输出运算的 FP32。新包大小 **23.50 MiB**。在 Apple M5 Pro 上用 Core ML `CPU_AND_GPU` 单独测量同一已保存输入，十次热预测的中位数 **12.19 ms**，P95 **14.10 ms**。首次预测耗时约 **5.98 秒**。这些模型调用计时排除了相机、缩放、跟踪与渲染。 [模型导出、计时和复跑记录](Model-YOLOE26s-PF-640-Mixed/README.md)

在九张真实 Bonn RGB-D 图像和两张合成图像上，混合精度 GPU 路径与 FP32 参考输入完全相同。置信度门限 0.25 时，两者均有 **86 条候选**，配对后 **86/86 类别一致**，实例掩膜平均 IoU **0.99525**，最小 **0.88732**。一个 `veterinarians office` 候选的原始分数从 **0.441308 升至 0.643066**。门限 0.10 时也观察到弱候选标签改变与掉到阈值以下。应用默认 **Reference**，将混合精度提供为手动切换的 **Efficient preview**。这批结果衡量模型转换的一致性，真实识别与边界正确率仍需独立真值评价。 [候选张量、分数异常与掩膜审计说明](Model-YOLOE26s-PF-640-Mixed/README.md)

检测模型的 `CPU_AND_NE` 初次冷编译受共享编译服务占用影响，未在有界窗口完成；服务空闲后复测成功，同一张保存帧的八次热调用中位数 **21.68 ms**、P95 **24.26 ms**。其 Core ML 静态计划优先把 319 个操作、84.46% 估算成本分配给神经引擎，这不是运行时硬件利用率测量。七个高位类别索引精确保留，但个别原始分数出现 **0.174→0.027** 的明显变化。没有对该后端做完整多图掩膜审核或并发摄像头对照，因此本轮保留审核更充分的 CPU/GPU 高效预览路径。这里的 YOLOE 成功不代表下面的 SAM 编码器移植成功。[NE 复测记录](Model-YOLOE26s-PF-640-Mixed/performance-cpu_and_ne-retry.json)

### Camo 实况观察，与离线压力测试分开

v0.8 的 **Performance** 菜单已验证可在停止摄像头后切换 Reference 与 Efficient preview。1920×1080 Camo 输入、SAM 和自动深度均开启，在同一室内画面先后观察到：

| 配置 | 采集 FPS | 检测 FPS | 显示 FPS | SAM 更新 FPS | Fine 读数 | Callback-to-GPU P95 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Efficient preview | 30.0 | 29.6 | 28.9 | 3.2 | 20/22 | 66.7 ms |
| Reference | 30.0 | 25.5 | 24.8 | 3.1 | 19/23 | 96.8 ms |

这些是两次界面瞬时读数，不是相同录制输入、固定时长或独立重复的摄像头基准。高效模式的细轮廓 worker 为 248 ms、来源年龄 0.41 秒；参考模式为 336 ms、0.57 秒。画面中仍有 `car interior` 等明显不合场景的语义结果；不能据此声称误识别已降低。没有保存私有摄像头图像或录像。最终重建后又核对两次高效模式，检测为 29.7／29.8 FPS、显示为 29.2／28.7 FPS、SAM 为 3.7／3.6 FPS。停止后未发现存活的 SAM worker，再次启动后恢复细轮廓；这些仍是短时验证。[构建、源码哈希、实况读数与验证记录](../../../../model/yoloe26/native-validation-v08.json)

本轮还修复了两处运行状态问题：模型成功加载后才提交性能模式，加载失败保留原模型说明；停止任务使已排队 SAM 请求失效，关闭的 Python 输入管道返回可捕获错误。最终构建通过 59 项 Swift 测试；串行和异步短回放均有热测 SAM 结果，刻意缺失 worker 的运行保存无效报告并返回退出码 1。它们验证故障处理，不能替代长时稳定性测试。

### 1.2 SAM Core ML 编码器试验保留 FP32 MPS 路径

同一 SAM2.1 Tiny 权重的全 FP16 Core ML 编码器在 CPU-only 探针输出了非有限特征和空掩膜。保护注意力、归一化与 softmax 的混合精度版本得到有限特征，但其 CPU 编码加原 MPS 解码，在两张保存帧上的完整热调用中位数为 **285–290 ms**。原 FP32 MPS 完整路径为 **112–124 ms**。混合路径相对原路径的实例掩膜 IoU 为 **0.133–0.927**。精确 FP32 特征经同一桥接送回解码器，两个实例图均有 **0 像素变化**，帮助把偏差定位到转换后的特征。 [SAM 编码器实验、权重和安全复跑命令](../../../../.cache/model-sam-experiment/summary.json)

混合版本用 `ALL` 时触发 MPS 计算函数栈断言，未完成有效预测。全 FP16 的 `CPU_AND_NE` 冷编译在约 90 秒的试验窗口内未完成，ANE 性能仍未知。保留现有 FP32 MPS SAM 后端。 [完整故障与设备记录](../../../../.cache/model-sam-experiment/summary.json)

## 2. 已有研究解决到哪里

| 最接近的一手研究 | 已经解决的内容 | 对本项目创新声明的限制 |
| --- | --- | --- |
| [DVSNet，CVPR 2018，原文](https://arxiv.org/pdf/1804.00931) | 用决策网络按预期置信度在区域级选择昂贵分割或较便宜的光流传播 | “运动大就重算”“置信度低就细化”已有明确先例 |
| [Towards Streaming Perception，ECCV 2020，原文 §4–5、Fig.9](https://www.ecva.net/papers/eccv_2020/papers_ECCV/papers/123470460.pdf) | 联合评价延迟与准确性；动态调度、异步关联与预测；还讨论了预测框后变换实例掩膜 | 当前异步队列与框仿射传播属于合理工程，不能单独称重大算法创新 |
| [Lazy-XMem / Strike the Balance，ACCV 2024，方法全文](https://arxiv.org/html/2408.00169v1) | 用对象周围的归一化熵识别不可靠状态，在线请求用户纠正，兼顾长期跟踪与纠正负担 | “不确定时请求新证据”也已有先例；我们的自动计算资源与人的纠正不能混为一谈 |
| [EdgeTAM，CVPR 2025，方法全文](https://arxiv.org/html/2501.07256v1) | 同时优化图像编码与视频记忆注意力，并通过蒸馏构造移动端视频分割模型 | 仅替换较小编码器不是新的压缩思想；完整视频记忆也是必须比较的强基线 |
| [Adaptive Computation with Conformal Certification，2026-10 预印本，§3、§8](https://arxiv.org/html/2610.19189v1) | 在科学图像中校准粗到细计算的选择，并在其假设下约束丢弃信号 | “用校准来分配计算”本身也不能声称首创；该文的交换性条件和信号质量界并不自动适用于连续视频的边界误差 |

因此目前只能提出**候选研究空白**：对有实际返回延迟、多个目标共享编码成本的异步分割服务，估计“返回时的净边界收益”，并联合决定请求、传播及退回较快结果。上述文献足以排除几种过宽的创新表述；还不足以证明没有其他工作解决这一精确问题，投稿前需继续查引文与最新同题文献。

EdgeTAM 论文的 16 FPS 使用 iPhone 15 Pro Max；EfficientTAM 的 [2024 预印本](https://arxiv.org/abs/2411.18933)与[ICCV 2025 定稿](https://www.openaccess.thecvf.com/content/ICCV2025/papers/Xiong_Efficient_Track_Anything_ICCV_2025_paper.pdf)分别出现约 10 FPS 与 Mobile 变体约 28 FPS 的移动端结果。版本、模型和硬件不同，不能将较大的数字写成当前 Mac 或当前公开检查点的性能。

还应加入一个低成本传播对照：[Apple Vision 光流请求](https://developer.apple.com/documentation/vision/vngenerateopticalflowrequest)。它有原生接口，但 Apple 明确指出光流耗资源；必须把其计算、内存及遮挡失败计入总预算，不能假设光流一定比重算划算。

## 4. 一个值得验证的论文假设

暂定题目：**面向延迟返回精细分割的收益预测与预算约束流式实例感知**。

假设 H1：在检测器、输入观测、提示方式及实际精细分割预算相同时，预测“结果实际可用时相对快速分割的边界收益”，比固定间隔、固定 TTL 或只看当前不确定性的策略，能降低用户显示时刻的边界损失和错误轮廓持续时长，同时保持目标覆盖率与响应延迟。

具体预测量可以写成：

```text
Δ(i,t,τ) = E[ L(native(i,t+τ), GT(i,t+τ))
              - L(propagate(refine(i,t)), GT(i,t+τ)) | t 时刻可获得的历史 ]
```

其中 τ 是预计的完整返回延迟，L 先固定为 1−Boundary IoU；GT 只用于离线训练/校准与评价，在线策略不能读取。输入可使用原生掩膜边界形状、原生与既有细化掩膜的分歧、框变化、轨迹/类别稳定性、遮挡迹象、来源年龄和当前服务耗时。先训练一个小型回归/排序器或用校准表验证信号，不先训练大视觉基础模型。

策略不仅判断“难不难”，还判断“值得不值得现在算”：SAM 有时会把背景并入目标，返回时目标可能消失，原生分割也可能已足够好。收益可为负。一个编码器通常服务一帧中的多个框，因此成本应建模为**共享图像编码成本 + 所选框的解码成本 + 传输/合成成本**，而不是把每个框误算成一次完整 SAM 调用。

候选贡献应是可迁移的延迟条件收益估计与选择规则、明确的预算/撤回机制，以及真实边界真值下的因果对照。只有 Mac 原生封装或一个固定阈值规则，还不足以支撑期刊层面的算法贡献。

## 5. 为何现有仿射 + 0.65 秒期限不足

同一个框可以包含完全不同的手势、旋转的椅背或新遮挡物；IoU 和尺度稳定不能证明内部轮廓稳定。相同 ID/类别也不能排除错误关联。固定 TTL 在静止目标上可能过于保守，在快速形变目标上又可能过于宽松。共享实例 ID 图还会丢掉被更高优先级目标覆盖的像素，因而“缓存存在”不等于每个对象都有可用细化结果。

此外，旧实验已经出现一个重要混淆：串行和异步模式处理的帧不同，确认后的目标数也随之不同。这样的结果能解释吞吐变化，不能隔离调度对边界质量的影响。新研究必须把“相同观测下的策略效果”和“完整实时系统的效果”分成两层实验。

### 两段真实标注视频的首轮反例诊断

主任务已从官方 DAVIS 2017 数据中取得 `blackswan` 的 50 帧、`dance-twirl` 的 90 帧及其独立人工实例标注。这个小样本用于对照稳定外形与明显形变，属于选定的两序列诊断，不能代表整个 DAVIS。实验给传播器**完美来源 GT 掩膜、完美当前 GT 框和正确身份**，比较原地保留旧掩膜与框仿射传播；没有调用 YOLOE 或 SAM。来源间隔直接记为 1/3/6/12 帧，没有假定录制 FPS、秒数或 0.65 秒门限是否通过。

## 6. 可在本机推进的受控协议

**数据与真值。** 先用 [DAVIS 2017 官方 480p 图像、逐帧实例标注及评价代码](https://davischallenge.org/davis2017/code.html)建立小规模先导实验，按视频划分训练、校准和测试，不能将同一视频的相邻帧放入不同集合。正式结论覆盖完整预先声明的测试集合，并增加独立的困难视频集和 Camo 实拍。Camo 可先计划 12 段、每段 10–20 秒，含静止、平移、旋转、形变、互相遮挡和重现；数量是计划，当前尚未采集或标注。边界真值需人工逐帧核对，含身份；不能把 SAM 自身输出当独立真值。

**两种提示协议。** 产品协议让所有方法使用相同的 YOLOE 预测框、分数和轨迹，不将 GT 框/掩膜偷偷交给某个模型。另设标准 VOS 协议，让各视频模型共同使用相同首帧 GT 提示，用于理解模型上限；两张表分开报告，不能用其结果直接宣称自动识别能力。

**层一：冻结观测，隔离策略。** 缓存相同检测、原生掩膜、轨迹和候选 SAM 输出。每种策略只看当前与过去，按相同实际视频时间戳回放，记录请求开始/完成时间。费用用本机实测服务时间及编码/解码次数计算，另用 100/250/400 ms 返回延迟做预先规定的压力条件。未来帧只可用于离线评价与 oracle 上界。不能用循环播放 120 帧的现有压力测时替代该质量实验。

**层二：完整实时管线。** 在同一 Mac、相同电源/分辨率/目标上限下分开重跑各方法，交换运行顺序、至少三次独立运行，先预热再计时。保留真实队列丢帧、资源竞争、渲染与深度开关；没有物理显示计时设备时，把 Callback-to-GPU 叫软件链路延迟。Camo 相机验证与文件按时间播放回放分别标记。

**预算。** 同时报出完整编码次数、每次框数、解码次数、实际占用毫秒、完成/丢弃请求和峰值内存。以相同滚动预算和突发上限比较，并增加总实际计算时间匹配的结果；仅“调用次数相同”不足以控制多目标工作量。预算档位在测试前固定，例如 1/2/4 次图像编码每秒，并展示实际使用量；不可把这些档位写成已测性能。

## 7. 必须击败的基线与负对照

1. YOLOE 原生掩膜：始终新鲜、无额外 SAM，防止细化反而降低质量。
2. 当前 v0.7：固定后台请求间隔 + 框仿射 + 固定 0.65 秒门限。
3. 相同预算的均匀周期、随机周期和年龄优先刷新；至少三个随机种子。
4. 当前置信度/边界熵阈值、运动阈值、原生与传播掩膜分歧阈值；这是对通用“自适应”的强简单对照。
5. Apple 光流传播 + 相同刷新/回退规则；完整统计光流成本。
6. SAM2 视频记忆、可运行的 EdgeTAM/EfficientTAM 视频模型；共用提示协议，若 Mac 后端未跑通则如实标记未验证，不捏造 FPS。
7. 离线每帧细化和读取未来真值的最优请求时机：只作成本/收益上界，不能作为可部署方法。

消融至少包括：去掉预计返回延迟、去掉净收益而只预测当前误差、去掉类别/身份不确定性、去掉共享编码成本、去掉回退、固定 TTL 与自适应有效期、同一模型换另一种精细分割器。加入“将预计延迟随机打乱”的负对照，检验改进是否真的来自延迟信息。共享 ID 图合成与逐对象掩膜分开评价，防止重叠优先级改变被误当作分割提升。

## 8. 联合质量、时序与速度的判据

主结果采用**固定墙钟查询时刻的质量**：每个真实视频时刻评价那一刻实际已经可用并显示的结果，对齐当前 GT，而不是把迟到的好结果贴回它的历史来源帧。沿用流式评价思想，不把它包装成新指标首创。

| 方面 | 预先固定的报告内容 |
| --- | --- |
| 区域与边界 | DAVIS J、F；[Boundary IoU / Boundary AP 原论文](https://openaccess.thecvf.com/content/CVPR2021/html/Cheng_Boundary_IoU_Improving_Object-Centric_Image_Segmentation_Evaluation_CVPR_2021_paper.html)对应指标；帧对齐与墙钟对齐结果并列 |
| 覆盖与错误 | 漏检、误报、可见 GT 目标覆盖率；丢失按空掩膜计分，不能只评成功匹配目标；错误细轮廓显示时长及从精细模式退回次数 |
| 时序恢复 | 旋转/遮挡/重现后达到预定 J 与 Boundary IoU 阈值并保持连续三帧的延迟；未恢复次数、最长错误连续段、ID 变化；阈值需在测试前固定 |
| 系统 | 采集/检测/独特显示帧/SAM 更新率分别列出；来源年龄、软件延迟 P50/P95、任务完成率、实际调用/框数/占用时间、峰值内存 |
| 稳定性 | 静止片段轮廓抖动与边界误差一同报告；不能只用跨帧相似度奖励“冻结错误轮廓” |

以视频为统计单位做配对 bootstrap 置信区间，报告各视频与运动/遮挡子组；不能把高度相关的连续帧当独立样本堆大样本量。画出质量—计算时间、质量—P95 延迟的 Pareto 曲线，而不是只给一个 FPS。

一个先导的**预注册目标**可设为：相同预算下墙钟 Boundary IoU 提高至少 3 个百分点、错误细轮廓时长下降至少 20%，目标覆盖率下降不超过 1 个百分点且 P95 延迟不恶化。它们是待检验门槛，不是预期必然达到的结果；先导数据只能用于判断后续样本量，不能反复调阈值后在同一数据上宣布成功。

若只在静止场景、一个延迟档位或一个分割模型上有效，若加入真实资源竞争后消失，或优势来自少画目标/多用计算，H1 就不受支持。若简单周期策略或轻量视频模型已达到同等 Pareto 曲线，应接受更简单的产品方案，并将负结果作为研究判断而不是继续宣称创新。

## 9. 推进顺序与论文落点

混合精度检测复测、传播门限与实例像素缺失拆分，以及两序列 GT 反例诊断已经完成。下一步将 GT 评价接入真正模型输出及固定观测回放，测当前仿射与固定期限的墙钟损失。只有真值辅助对照显示同预算仍有明显调度收益，且收益能由在线信号预测，才投入小型收益估计器和策略训练。EdgeTAM 与 EfficientTAM 的可用性和精度探针放在基础评价器之后，以便分别估计换模型与换策略的收益。

拟主投 **Computer Vision and Image Understanding（CVIU）**：候选工作围绕视觉表示的使用、视频实例理解和精度/时序约束，有方法、失效分析与独立真实数据时较契合。该选择是研究规划，不是当前工程已达到录用水平。出版商当前检索可见的 [期刊发表选项](https://www.sciencedirect.com/journal/computer-vision-and-image-understanding)列有 Subscription 路径，作者无发表费；本轮直接打开正文返回 403，因此不把可选 OA 价格或未来政策写成已完整核实的承诺，投稿前需再次核对指南与特殊费用。期刊适配不能替代方法新颖性与实验强度。

价值对象是本机 AR 叠加、交互选物、机器人/移动端视觉开发者：他们需要知道昂贵细节何时仍然可信，以及什么时候应立即用较粗的新结果取代漂亮但过期的结果。即便最终证明复杂策略不划算，也能得到可复用的判断条件、真实质量—延迟边界和稳定产品。
